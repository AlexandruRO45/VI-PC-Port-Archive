# راهنمای شروع سریع Leonida

مستندات انگلیسی مرجع رسمی است. این راهنما بر پایهٔ نسخهٔ `867d922` نوشته شده و فقط مراحل اصلی شروع کار را پوشش میدهد.
برای دیدن وضعیت فعلی پروژه به [README انگلیسی](../../../README.md#project-status) و برای جزئیات بیشتر به [فهرست مستندات](../../README.md) مراجعه کنید.

## Leonida چیست؟

Leonida یک پروژهٔ بازترجمهٔ ایستا (static recompilation) است که نسخهٔ Xbox Series بازی Grand Theft Auto VI را به صورت بومی روی Windows اجرا میکند.
پروژه روی رایانهٔ خودتان و از نسخهٔ شخصی خودتان از بازی ساخته میشود. برنامه های شیدر RDNA2 به SPIR-V ترجمه میشوند تا با Vulkan کار کنند،
مدل ها، تکسچرها و صداها از بستهٔ محلی بازی خوانده میشوند و رابط های سیستمی که بازی لازم دارد دوباره پیاده سازی شده اند.

مخزن (repository) شامل بازی، فایل اجرایی یا کلیدها نیست. ابزارها فقط فایل هایی را میخوانند که از قبل روی دیسک قابل خواندن هستند و
نه رمزگشایی میکنند و نه حفاظتی را دور میزنند. فایل های بازی و خروجی های ساخت را روی رایانهٔ خودتان نگه دارید. هنگام گزارش مشکل یا ارسال
درخواست ادغام (pull request) آن ها را پیوست نکنید و لاگ هایی که از آن ها نقل قول میکنند هم پیوست نکنید.

## پیش نیازها

- **نسخهٔ شخصی خودتان** از بستهٔ Xbox Series با نسخهٔ `1.0.2.1`. پوشه ای را انتخاب کنید که `MicrosoftGame.Config` و آرشیوهای `.rpf` را به صورت فایل معمولی دارد.
- Windows 10 یا 11 با معماری x64 و حدود **400 گیگابایت** فضای خالی برای فایل های کاری. این عدد برای ساخت کامل است
  و اندازه ها همان طور است که Windows Explorer نشان میدهد (GiB). برای فقط اجرای بازی، `--stages check,shaders,runtime` حدود 30 گیگابایت لازم دارد و
  مرحلهٔ `assets` به تنهایی حدود 370 گیگابایت میخواهد. با `--work` و `--out` میتوانید این فایل ها را روی دیسک دیگری بگذارید.
- Git، [Python 3.12 یا جدیدتر](https://www.python.org/downloads/) و [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).
  هنگام نصب Python روی Windows گزینهٔ افزودن `python.exe` به `PATH` را فعال کنید.
- [Vulkan SDK](https://vulkan.lunarg.com/) برای ابزارهای `spirv-as`، `spirv-val` و `vulkaninfo`.
- [LLVM 21 یا جدیدتر](https://github.com/llvm/llvm-project/releases) با پشتیبانی **AMDGPU** در `llvm-mc`.
  نسخهٔ رسمی LLVM برای Windows این پشتیبانی را ندارد. از ریشهٔ مخزن، در PowerShell فایل `scripts\build_llvm_mc.ps1` را اجرا کنید تا
  یک `llvm-mc.exe` بومی بسازد؛ این اسکریپت به Git و ابزارهای C++ در Visual Studio نیاز دارد، متغیر `LLVM_MC` را تنظیم میکند و حدود 20 تا 40 دقیقه طول میکشد.
  پس از پایان، یک پنجرهٔ PowerShell جدید باز کنید.
  اگر از [conda](https://docs.conda.io/) استفاده میکنید، راه سریع تر این است: `conda install -c conda-forge llvm-tools`
  (نسخهٔ Windows آن هدف AMDGPU را دارد و [راهنمای تست ها](../../testing.md) نسخهٔ 23.1.6 را به کار برده است).
  سپس `LLVM_MC` را روی مسیر کامل `llvm-mc.exe` نصب شده تنظیم کنید. پس از فعال سازی محیط، دستور `where.exe llvm-mc` مسیر آن را نشان میدهد
  (در PowerShell دستور ساده ی `where` همان `Where-Object` است).
  اگر `llvm-21` را روی Ubuntu در WSL نصب کرده اید، `LLVM_MC` را در همان پنجرهٔ PowerShell که ساخت را از آن اجرا میکنید تنظیم کنید.

  ```powershell
  $env:LLVM_MC = 'wsl -d Ubuntu -e /usr/lib/llvm-21/bin/llvm-mc'
  ```

- Visual Studio 2022 با بستهٔ **Desktop development with C++** و Windows SDK نسخهٔ `10.0.26100` یا جدیدتر برای ساخت بخش runtime.
- [ffmpeg](https://ffmpeg.org/download.html) در `PATH`؛ اختیاری است و برای رمزگشایی XMA2 به کار میرود، اما با `--wav` الزامی است.

آیا رایانهٔ شما برای این کار به اندازهٔ کافی قوی است؟ قبل از یک ساخت طولانی، دستور `python -I tools/pc_checker.py --cli` پردازنده، کارت گرافیک و حافظه را
شناسایی میکند و با نمایه های مرجع مقایسه میکند. جزئیات بیشتر در [README انگلیسی](../../../README.md#how-to-build) آمده است.

## ساخت روی Windows

پس از نصب پیش نیازها، مخزن را همراه با زیرماژولش کلون کنید.

```powershell
git clone --recursive https://github.com/ItsNotRexed/Leonida
cd Leonida
```

روی `Build.bat` دوبار کلیک کنید. برنامه نسخهٔ شما را روی رایانه پیدا میکند. اگر بیش از یک نسخه بیابد از شما میپرسد کدام را میخواهید
و اگر هیچ نسخه ای نیابد مسیر پوشه را میخواهد. پیش از شروع، ابزارها و فضای خالی را بررسی میکند. نتیجه به طور پیش فرض در
`Documents\Leonida` ذخیره میشود و اگر ساخت متوقف شود میتوانید از همان جا ادامه دهید.

### ساخت از PowerShell

دستورها را از ریشهٔ مخزن اجرا کنید. `--find` نسخه های پیداشده روی رایانه را فهرست میکند و `--check` فقط بسته را بررسی میکند.
`--full-check` علاوه بر آن SHA-256 هر فایل را هم مقایسه میکند که ممکن است زمان بر باشد. در دستور ساخت، مسیرها را با مسیرهای رایانهٔ خودتان جایگزین کنید.

```powershell
python -I make_game.py --find
python -I make_game.py --pick
python -I make_game.py --check
python -I make_game.py --check --full-check
python -I make_game.py --game "D:\path\to\package" --out "D:\Games\Leonida" --work "E:\leonida-work"
```

ترتیب مرحله ها این است: `check`، سپس `shaders`، `assets`، `runtime` و در پایان `pipelines`.
با `--stages shaders,assets` میتوانید فقط برخی مرحله ها را انتخاب کنید. ترجمهٔ شیدرها معمولاً طولانی ترین مرحله است و
تعداد فرایندهای آن با `--jobs` تنظیم میشود. گزینهٔ `--wave64-emulate` را روی مقدار پیش فرض `auto` بگذارید، مگر اینکه لازم باشد انتخاب ابزار را عوض کنید.
گزینهٔ `--wav` از جریان های Ogg Opus نسخهٔ PCM WAV هم میسازد و فضای بیشتری میخواهد.

روی ترمینال تعاملی، یک صفحهٔ تنظیمات LEONIDA برای انتخاب تعداد jobs و همپوشانی مرحله ها نمایش داده میشود و سپس نمای لاگ هر مرحله
(با کلیدهای `1`–`4` و `Tab`) را میبینید. لاگ کامل هر مرحله در `work/logs/` ذخیره میشود. برای کنسول ساده از `--no-tui` استفاده کنید.

### ساخت روی Linux

`make_game.py` روی Linux هم کار میکند و اگر `llvm-mc` در `PATH` باشد آن را خودکار پیدا میکند؛ مطمئن شوید نسخه اش از AMDGPU پشتیبانی میکند.
لودر بازی یک برنامهٔ Windows است و از طریق Wine یا Proton اجرا میشود. اگر یک ساخت Windows آمادهٔ لودر دارید،
پوشهٔ آن را با `--runtime-build` بدهید. به [راهنمای ساخت و اجرا روی Linux](../../../README.md#running-the-loader-on-linux) نگاه کنید.

## رفع مشکلات رایج

- **پس از دانلود ZIP، زیرماژول وجود ندارد.** مخزن را با `--recursive` کلون کنید، مثل مثال بالا.
  اگر مخزن را قبلاً کلون کرده اید، از ریشهٔ آن `git submodule update --init --recursive` را اجرا کنید.
- **`llvm-mc` هدف `gfx1013` را رد میکند.** بررسی کنید نسخه ای را به کار میبرید که از AMDGPU پشتیبانی میکند و `LLVM_MC` به ابزار درست اشاره دارد.
- **CMake یک Windows SDK جدیدتر میخواهد.** نسخهٔ `10.0.26100` یا جدیدتر را از Visual Studio Installer نصب کنید و سپس پوشهٔ ساخت را دوباره پیکربندی کنید.
- **فضای دیسک سیستم کافی نیست.** با `--work` فایل های کاری را روی دیسک بزرگ تری بگذارید و اگر خروجی را هم میخواهید جابه جا کنید از `--out` استفاده کنید.
- **Windows اجرای ابزارهای تست ساخته شده روی رایانه را مسدود میکند.** به [مشکلات شناخته شده در راهنمای تست ها](../../testing.md#known-problems) مراجعه کنید.

## مشارکت

1. [راهنمای مشارکت](../../../CONTRIBUTING.md) را بخوانید و پیش از شروع، [issue هماهنگی][coord] و درخواست های ادغام باز را ببینید.
2. کار را با کامنت `claiming: <ID>` در issue هماهنگی رزرو کنید، یا اگر هنوز شناسه ندارد یک توضیح یک خطی بنویسید.
3. تست های مناسب را با ورودی های ساختگی اجرا کنید. برای تغییرات مستندات، مثلاً میتوانید از ریشهٔ مخزن `python -I tests/test_docs_links.py` را اجرا کنید.
4. در درخواست ادغام، شناسهٔ کار یا لینک کامنت رزرو و تست هایی را که اجرا کرده اید بنویسید. اگر روی GPU تست کرده اید، کارت گرافیک و نسخهٔ درایور را بنویسید
   و هر کمکی را که از هوش مصنوعی گرفته اید ذکر کنید.

[راهنمای تست های GPU](../../testing.md) توضیح میدهد چطور بدون فایل های بازی تست ها را اجرا کنید.
نتایج را در [issue شمارهٔ 166](https://github.com/ItsNotRexed/Leonida/issues/166) منتشر کنید.
