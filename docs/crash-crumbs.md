# Light GPU crash diagnostics (Windows)

Set `VICTORY_CRUMBS=1` in a build with `diagnostics` to collect crash context without full DRED. For a separately approved title run through `wt/scripts/run-victory.ps1`, use `-Diag -NoDebugLayer -NoDred` to keep the launcher's full DRED and debug layer off. Unset `VICTORY_GPU_TIMING`, `VICTORY_D3D12_GBV`, `VICTORY_TRACE_SHADERS`, and any capture/dump settings for a comparable run. `VICTORY_CRUMBS` itself enables native DRED auto-breadcrumbs at device creation, forces DRED page-fault collection off, and does not set markers or insert GPU timestamp queries. Explicit full DRED (`VICTORY_D3D12_DRED`) still takes precedence for page-fault collection and detailed notes.

- `GPU memory sample` is emitted about once per second from a separate thread. The DXGI `LOCAL` and `NON_LOCAL` usage/budget pairs are in bytes, queried on node 0 of the D3D12 device's adapter LUID. Also logged: working set, private commit, physical RAM available, system commit/limit, and the process hard-fault delta across consecutive samples (not all page faults and not a rate). `sample_ms` is the actual interval; missing counters are `None`. The first sample has no hard-fault delta.
- `crash submission` and `crash list` lines are emitted only on the host's fatal path. The last 24 D3D12 submissions retain up to the last 12 physical command lists each (`Title`, `Prelude`, `Upload`, `Present`). Each list retains its last eight recorded title draws, dispatches or indirect calls, including the mesh fallback dispatch and draw separately. Shader hashes are short title shader hashes from the pipeline. A copy/barrier-only list may have no recorded ops. A ring tail is recording context, not proof that the GPU reached an operation; correlate with native progress using `raw` (the command-list pointer, reusable across submissions).
- Submission ID is the expected host fence value. `frame` is the most recent queue present count at submission; `elapsed_ms` is CPU wall time from just before `ExecuteCommandLists` until fence observation/failure, not GPU execution time. `fence_observed=Some(18446744073709551615)` is the D3D12 removal sentinel. `Complete` confirms fence observation; it does not rule out a device reset detected immediately afterward. Earlier entries can be overwritten by design.
